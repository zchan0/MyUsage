Spec 15 · UI mockup v3

Multi-account — swipeable cards + inline Settings management

v3 reframes around what's actually achievable given the data layer. Provider CLIs hold one credentials artifact at a time and session JSONLs carry no account ID, so MyUsage can only see active account data live. Inactive accounts are last-active snapshots cached locally per (provider, email).

Storage: single ~/Library/Application Support/MyUsage/accounts.json atomic-write file holding both per-account snapshot cache + a tiny registry (firstSeenAt / lastActiveAt). SQLite would be over-engineered for ~10–20 keyed records that get rewritten on every refresh.

Settings: account management folds into the existing Providers tab as inline sub-rows under each provider (only shown when N ≥ 2). No new tab — the N=1 case (90 % of users) doesn't justify a whole tab of its own.

Demo F · Forget confirmation

Forget asks once — explains exactly what will happen.

Destructive in spirit (drops cached snapshot + re-tags ledger rows back to default) but reversible in practice (the account reappears the next time MyUsage observes it). Confirm text spells out both halves so users aren't surprised.

Storage shape

Single file at ~/Library/Application Support/MyUsage/accounts.json: 

{
  "snapshots": {
    "claude:user@company.com": {
      "snapshot": { /* full UsageSnapshot Codable */ },
      "lastRefreshedAt": "2026-05-09T14:21:08Z"
    },
    "claude:me@personal.dev": {
      "snapshot": { /* … */ },
      "lastRefreshedAt": "2026-05-06T14:20:11Z"
    },
    "codex:me@personal.dev": { … }
  },
  "registry": {
    "claude:user@company.com": {
      "firstSeenAt": "2026-04-12T09:00:00Z",
      "lastActiveAt": "2026-05-09T14:21:08Z"
    },
    "claude:me@personal.dev": {
      "firstSeenAt": "2026-04-15T11:30:00Z",
      "lastActiveAt": "2026-05-06T14:20:11Z"
    }
  }
}

Forget semantics

  • Drop the snapshots[key] entry → card disappears from popover swipe.
  • Drop the registry[key] entry → drops off Settings list.
  • UPDATE ledger_entries SET account_id = "default" WHERE account_id = ? → preserves cost numbers, drops account label so totals stay correct.
  • Reversible: if the user signs in to that account again later, MyUsage observes the email and starts a fresh registry/snapshot entry. Old "default"-re-tagged rows stay anonymous.

What changed from v2

  • Inactive accounts now have a real card. v2 tried to invent a "ledger snapshot" sub-card with cost + per-model — but those numbers can't actually be sourced (historical JSONLs carry no account ID). v3 shows the snapshot of when the account was last active — data we genuinely have.
  • Stale banner makes "this is historical" unmistakable. Plus a saturate(0.65) filter on the inactive card.
  • Settings management surface defined. No new tab — folds into Providers as inline sub-rows.
  • Storage shape pinned down. Single accounts.json file, atomic write.

Honest constraints (carry into spec doc)

  • Inactive snapshots are frozen at last-active time. The 5h / Weekly bars on an inactive card show the state at that moment, not now. The reset countdown in the bar foot shows what was in effect then — useful as historical context, misleading if read as live.
  • Forward-only attribution. Pre-multi-account ledger rows stay default forever. If a user only ever signs in as one account, MyUsage looks identical to today.
  • Account list grows monotonically until the user manually Forgets. There's no automatic GC — if you sign in to 50 accounts over time and never forget any, you'll have a long Settings list. Acceptable; common case is 1–3 accounts per provider lifetime.
