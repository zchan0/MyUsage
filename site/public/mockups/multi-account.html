Spec 15 · UI mockup v2

Multi-account popover — every account visible at a glance

v1 hid inactive accounts behind a click. v2 keeps every account visible without interaction: active account shows its live 5h + Weekly bars; inactive accounts show a compact monthly snapshot (cost + per-model chips) directly below. One scan top-to-bottom and you've seen them all.

Constraint that drives the layout: live utilization data (5-hour, weekly) only comes from API calls, which only succeed for the currently signed-in account. Inactive accounts are visible to MyUsage only through the multi-device ledger (historical $ + per-model breakdown). The mockup reflects this asymmetry honestly — active gets bars, inactive gets the snapshot we actually have.

Visual legend

Active — credentials currently point at this account. Sage filled circle with soft 18 % halo. Bars are live (5-hour / Weekly utilization from API).

Inactive — observed historically; ledger has data. Sage hollow ring. Block shows monthly $ + per-model chips (no live bars — we can't fetch its API without its credentials).

What changed from v1

  • Inactive accounts no longer hidden behind a click. v1 reduced inactive accounts to a $ amount in a tiny strip; you couldn't see any usage info without clicking. v2 shows what we have inline: monthly cost + per-model breakdown.
  • Active account gets an explicit email header. Previously the bars were untagged — confusing once 2+ accounts exist. Now there's no ambiguity which account the bars belong to.
  • Cost row label flips to "All accounts" when N ≥ 2. Was "This month" (which is technically still correct but now the sum semantic matters more).
  • Click-to-expand interaction removed. Inactive blocks already show everything we have; nothing left to expand into.

Honest limit (worth flagging in spec)

  • We cannot show live 5-hour or weekly utilization for inactive accounts. Their credentials aren't available — Claude/Codex/Cursor CLIs only hold one auth artifact at a time. The historical ledger view (monthly cost + per-model) is the closest we can get for inactive accounts.
  • "Active" can change between refreshes if the user runs claude logout && claude login as a different account. The next refresh re-derives identity and the previously-active account becomes inactive (its data flows from API + ledger to ledger-only).
