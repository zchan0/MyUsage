Spec 15 · UI mockup

Multi-account popover

Layout B from spec 15: one card per provider, with a compact accounts strip appearing only when ≥ 2 accounts have been observed. The strip lives below the headline 5h / Weekly bars and above the cost row — small enough that single-account users see no change, structured enough that multi-account users see all accounts at a glance.

Each demo shows the popover in light + dark side by side so visual review covers both modes without toggling. All widths are pixel-faithful to the live 340 pt popover.

Single account — strip is invisible.

The 99 % case. When MyUsage has only ever observed one account for a provider, the accounts strip never renders. Existing single-account users see exactly today's UI.

Pulled from spec 15. Drives both the popover and the notification side. Each rule tested, each row independently verifiable.

Visual legend

Active — credentials currently point at this account (will be filled in for fresh data on every refresh).

Inactive — account observed historically; ledger has rows for it. Click the row to see per-device contributions and a per-model breakdown.

Anti-patterns rejected

  • Switch-account dropdown (hides accounts behind a click — defeats glance-ability)
  • Modal overlay for expanded view (popover-in-popover feels wrong on macOS)
  • Chevron / "view" affordance on each inactive row (too SaaS-feeling; row hover is enough)
  • Account aliasing UI in v1 (deferred — email is recognizable enough)
  • Per-account warn/crit thresholds in v1 (deferred — same threshold for every account)
